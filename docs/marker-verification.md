## 曾经的误判与真正根因

排查过程中一度得出"标记从未渲染"的错误结论。真正原因是**测试取样条件错误**：

探针从 `HaulableEver` 直接取前 N 个物品，**这些物品全部位于远古遗迹内部**，头顶有屋顶、被遮挡。标记即便按坐标画出来也被挡住，像素比对恒为 0，于是被误判成"没有渲染"。

### 修正后的取样条件（缺一不可）

1. 在当前视野内（`CameraDriver.CurrentViewRect`）
2. 未迷雾（`map.fogGrid.IsFogged == false`）
3. 头顶无屋顶（`map.roofGrid.Roofed == false`）

另加两项便于观察：相机拉近到 **20 格视野**（0.3 格标记约 20px）；自动选中一个物品，让检查面板显示「所属」，作为不依赖渲染的独立证据。

## 评估方法（可复现）

1. 游戏内 `ScreenCapture.CaptureScreenshotAsTexture()` 抓帧，不依赖外部截图
2. 抓两帧"都开"作为**噪声基线**，信号必须显著高于它
3. 逐锚点用 `WorldToScreenPoint(物品位置 + 标记层高)` 定位；同时测 `y` 与 `H-1-y` 规避坐标轴方向差异
4. A/B/C 三帧落盘 PNG，数字与图像可互相复核
5. 判定：信号 > 噪声×3，且达标锚点数 ≥ min(3, 屏内锚点数)

## 教训

**"看不到像素"不足以判定"没有渲染"** —— 必须先确认被测对象本身是可见的（未迷雾、无屋顶遮挡、在视野内）。该规则已写入 `RULES.md`，后续所有涉及可见性的测试都必须遵守。
